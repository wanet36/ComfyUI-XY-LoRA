## 三、为什么有的 .png 有的 .jpg

- **节点截图**（00、01、03、04、07、09、10）：界面文字多，用 PNG，边缘和小字不会被压糊；
- **出图结果**（05、06、08）：本质是照片，PNG 会到 1~2.6 MB，转成 JPG（质量 92）后 200~500 KB，放大看也看不出差别。

以后加图沿用这个规则就行。

## 四、尺寸约定

README 里用 `<img width="...">` 控制显示宽度，图片本身保持原始分辨率（高分屏截图直接丢进来，不用手动压）：

| 类型 | 显示宽度 | 原图宽度 |
|---|---|---|
| 整条工作流 | 1000 | 1000~1200 |
| 节点本体 | 400~430 | 500~1000 |
| 拼图结果 | 880~1000 | 1600 |
| 单张效果 | 360 | 800~900 |

`00-workflow.png` 原始截图是 2445×297，右边一半是空画布，已裁到 1105×297；以后再截全景记得先缩放到节点占满画面，别留大片空白。

## 五、核对命令

```bash
# README 引用了哪些图
grep -o 'images/[a-z0-9.\-]*\.\(png\|jpg\)' ../README.md | sort -u

# 目录里实际有哪些图
ls *.png *.jpg
```

两边一致即可。缺图时 README 只显示 alt 文字，不会报错。
